# 40 — 反向输入框：热键呼出，打中文出英文（或整理好的提示词），Enter 贴回原处

（与已完成的 `40-barwindow-split.md` 同号，引用时请带上文件名。）

**What to build:** 落实 Xtranslate 调研（docs/research/2026-09-27-xtranslate-analysis.md §1–§3）的
"反向翻译输入法"：在任何输入框里按热键呼出一个小框，直接打中文；手一停 300ms 就自动出英文；
Enter 把结果贴回原来的输入框，Esc 关闭。它解决的是"回英文帖要开翻译 → 复制 → 切回 → 粘贴"
这一连串折腾。

配合票 42 的提示词模板，同一个框也是写 vibe coding 提示词的地方：选「提示词优化」，打一句
中文需求，按两下 Enter，整理好的英文提示词就进了 Cursor 或 Claude Code 的输入框。

正向的面板用来"看懂别人"；反向输入框用来"回复别人、写给 AI"。两者互补，不是再造一个面板。

## 交互规格

- **呼出**：按全局热键（默认 Alt+Q，见「热键」一节）后：
  1. 记下前台窗口（`ForegroundWindow.Current()`，与窄条粘贴模式同一做法）；
  2. 小框出现在目标输入框的插入符旁。票 26 已有现成做法：`ScreenGeometry` 经 GetGUIThreadInfo
     取插入符位置，取不到就退到鼠标位置；
  3. 激活小框并聚焦输入框。
- **接受焦点**：与面板相反，反向输入框必须激活，因为它要接收键盘输入——这一点同快速条和窄条
  粘贴模式（ADR-0007）。失焦即隐藏；但显示后 300ms 内的失焦忽略，防止刚弹出就被自己触发关掉。
- **长高**：
  - 输入框随内容长高（52→180px），整窗高度钳制在 80–800。
  - 默认贴在插入符下方；下方空间不够时翻到上方。翻到上方后保持底边贴着锚点、向上长
    （`y + 旧高 − 新高`）。
  - 翻转与钳制复用 BadgePlacement。
- **方向**（Tab 循环，当前状态显示在底部的方向 chip 上）：
  - **翻译类模板**：在"自动 / 中→英 / 英→中"之间循环。
    - "自动"按 Xtranslate 的规则判定：汉字数 ×5 ≥ 拉丁字母数 → 中→英，否则英→中。
    - **不用 `LanguageGuess` 的 ×2 权重。** 反向输入框里中文夹英文术语是常态，"帮我 fix 这个
      bug in login.ts"按 ×2 算会被判成英文、反过来译成中文。
    - 为此新写一个反向专用的判定函数，不改 `LanguageGuess`——面板的方向标签和回声换向的
      行为都有测试钉着。
  - **改写类模板**：在"输出英文（默认）/ 输出中文"之间切换。反向输入框是"往外写"的地方，
    提示词优化默认就该出英文，不能因为输入碰巧是英文就输出中文。
  - 方向最终落成 `TranslationRequest` 的源语言和目标语言，模板里的 `{target}` 随之代入。
- **模板**（Ctrl+E 循环，当前状态显示在底部的模板 chip 上）：消费票 42 的提示词模板。
  - Ctrl+E 与面板的模板按钮共用同一个循环列表（票 42 的 `TemplateCycle`）。
  - 点模板 chip 弹出完整列表，包括不在循环里的模板。反向输入框接受焦点，普通的弹出菜单在
    这里没有面板那样的焦点问题。
  - 启动时的模板取 `AppSettings.ReverseInputTemplateId`（默认 `colloquial`）。为此，本票在票 42
    的「提示词模板」设置控件里加一列"输入框默认"。
  - 运行中切换模板只改运行时状态、不写设置，理由同票 42：写设置会重建热键注册表，还会重报
    热键冲突气泡。
  - `PromptTemplatesApply` 为 false（免费引擎）时，模板 chip 隐藏，请求按标准模板构建。反向
    输入框照样能用——按 ADR-0013 默认用免费引擎的新用户，不配任何东西也能用。
- **什么时候开跑**：
  - 翻译类模板：手一停 300ms 就自动跑（Xtranslate 的状态机）。
  - 改写类模板：**不自动跑**，按 Enter 才跑。它的输出长、费 token，每停一下就跑一遍，既慢
    又贵。
- **Enter 统一表示"往前走一步"**：
  - 输出已经对应当前输入 → 贴回。
  - 输出已过期（输入改过）或还在跑：
    - 翻译类 → 标记 wantCommit，译文一到就自动贴回（Xtranslate 的做法：短句翻译不必先复核）；
    - 改写类 → 还没在跑就开跑；跑完**停下，等第二次 Enter**。整理出来的提示词要先过目再贴。
  - Shift+Enter 换行。
- **竞态守卫**：
  - 新的输入会取消在途请求（CancellationToken + 序号）；
  - 与上一次完全相同的（原文、方向、模板）组合不重复请求；
  - 等待期间旧输出淡显，尾部挂与面板相同的静态 accent 光标块（票 22），不另做闪烁动画。
- **IME**：WPF 里组字中的按键以 `Key.ImeProcessed` 到达，组字中的 Enter、Esc、Tab 一律交给
  输入法。**不要照搬窄条的"ImeProcessed 归一到真实键"**：那是为了让字母动作在中文输入法下也
  能触发（票 24/26），这里要的恰恰相反。
- **Esc**：取消在途请求并关闭，不贴回。
- **错误**：失败态用 `TranslationUserErrorMapper` 给出的人话（与面板一致），并附"去设置"。

## 回贴链路（复用窄条粘贴模式，只补缺的两块）

- **基线照窄条粘贴模式（票 26）**：呼出时记下 `ForegroundWindow` → 隐藏自己 →
  `ForegroundWindow.Restore()` → `SelectionCapture.Paste(text)`。最后一步负责写剪贴板并发
  Ctrl+V，已经处理了修饰键残留。
- **补一：把前台抢回来的兜底。**
  - 只有 `Restore()` 之后前台仍不是目标窗口时，才走 Xtranslate 的强制序列：
    `AllowSetForegroundWindow` → `AttachThreadInput`（把前台线程、目标线程挂到本线程，每一对
    挂不上都容错）→ 发一次 F24 → `SetForegroundWindow` → 按相反顺序解挂。
  - 前台已经是目标窗口时，什么都不发。
  - 绝不发 Alt：单按 Alt 会激活记事本、Office 的菜单栏，吞掉随后的 Ctrl+V。
  - 这段放进 Shiyu.Windows 的 `ForegroundWindow`，窄条粘贴模式顺带受益。
- **补二：有条件地还原剪贴板。** 窄条粘贴不还原，因为把内容留在剪贴板上是剪贴板管理器的本分；
  而反向输入框的结果只是"运输"，不该占掉用户原来的剪贴板。
  - 写入前先快照：文本、HTML、RTF、文件列表，也就是 `WindowsClipboardWriter` 能写回去的格式。
    快照里有图片之类写不回去的格式时，不还原。这是已知局限：剪贴板上会留下译文，原来的图片
    仍可在历史里找到。
  - **快照带排除标记（`ExcludeClipboardContentFromMonitorProcessing` 或
    `CanIncludeInClipboardHistory`）时不还原。** 写回时这些标记会丢，密码就会以没有标记的形式
    重新出现在剪贴板上，被 Win+V 历史之类的工具记下来。
  - 用剪贴板序列号来判定：写入后记下序列号，400ms 后序列号没变才还原。这比 Xtranslate 的文本
    比对更准——用户在这期间复制了别的东西，就不去覆盖它。
  - 写入和还原都经过 `WindowsClipboardWriter`（拾语作为 owner），剪贴板监听会按 owner 跳过它们
    （WindowsClipboardMonitor.cs:79）：**不产生历史条目，也不弹徽标**。要用测试或探针钉住。
- **时序**：沿用窄条的时序，目前没发现需要额外等待。若实机出现第一个字丢失，再加上 Xtranslate
  的 60ms 等待。

## 热键

- 新增 `HotkeyAction.ReverseInput` 和 `AppSettings.ReverseInputHotkey`（默认 `Alt+Q`），接入以下
  几处：
  - `HotkeyPlan`：解析与两两冲突检查，全局键从 5 个变成 6 个；
  - `HotkeyModule` 的动作表；
  - KeyMap（名称"反向输入"）；
  - 设置·快捷键页；
  - 托盘菜单的动作行（带加速键列）。
- **已知冲突**：在 Microsoft 365（Word、Excel、PowerPoint、Outlook）里，Alt+Q 是"跳到搜索框"。
  这是应用内快捷键，`RegisterHotKey` 不会报冲突，注册后会悄悄把它盖掉。设置项的 Hint 要写明，
  用户可以自己改键。

## 后端与边界

- 后端走现有的 `BuildTranslationBackend()`：自备密钥 → 大模型流式输出；免费引擎（票 41）→
  分块逐段输出，模板不生效。
- 不进历史：输入框里打的原文、贴出去的结果，都不记成条目——这是运输，不是复制。
  "记录发出去的内容"留作后续。
- 方向只做中↔英，这是反向输入框的核心场景；其他外语留作后续。
- 依赖票 42 交付的模板层。口语 prompt、提示词优化、`<text>` 框定、按类别清洗都在 42 里，本票
  不重复实现。

**价值:** 拾语从阅读工具变成写作工具：回英文帖、写英文邮件、写代码评论，以及把随手写的需求
整理成给 AI 的提示词，都在当前输入框里完成，不用切窗口。
