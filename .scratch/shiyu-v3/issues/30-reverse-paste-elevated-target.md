# 30 — 反向输入框：目标窗口以管理员身份运行时，不贴，把译文留在剪贴板并提示

**来源：** 票 43 实现记录里的已知局限；CHANGELOG「[未发布] · 已知问题」
**Blocked by:** —（43 已合入）
**Status:** ready-for-agent（修复票，不受 WIP 上限约束，见 issue-tracker.md）

**问题：** Windows 的用户界面特权隔离（UIPI）会静默丢弃低完整性级别进程发往高完整性级别
窗口的模拟输入。拾语以普通权限运行，对以管理员身份运行的窗口发 Ctrl+V 时，`SendInput`
不报错，按键却被吞掉；约 0.4 秒后，条件还原又把剪贴板换回原来的内容。结果译文既没贴上，
也不在剪贴板里，用户什么都拿不到。

**What to build:**

- **回贴前先判断**：目标窗口所属进程的完整性级别是否高于本进程。取值路径：
  `GetWindowThreadProcessId` → `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` →
  `OpenProcessToken` → `GetTokenInformation(TokenIntegrityLevel)`。拿不到令牌时（通常恰恰
  因为对方是提权进程）按"高于"处理。
- **高于本进程时**：不发 Ctrl+V，也不做条件还原。译文留在剪贴板，托盘提示"目标程序以管理员
  身份运行，拾语无法直接粘贴；译文已放在剪贴板，请按 Ctrl+V"。复用票 43 已有的
  `ReversePaste.Leave` 路径。
- **判定放在 Core**：做成纯函数，输入是两个完整性级别，或"拿不到令牌"；Win32 只做取值的
  薄壳。
- **窄条的快速粘贴有同样的问题**：它不还原剪贴板，条目还在剪贴板里，只是没贴上。同一判定
  也接上，提示文案按场景区分。

**验收：**

- [ ] 单测：完整性级别比较——相等、更高、更低、拿不到令牌
- [ ] 实机（进 docs/manual-test-v6.md）：以管理员身份运行记事本，按 Alt+Q 打中文 → Enter：
      不贴，托盘提示，再按 Ctrl+V 贴出的是译文；普通记事本照常贴回，剪贴板照常还原
