实施记录（2026-10-01/02）：`LowLevelHookThread`（891b1f4）——每钩一条后台泵线程、构造同步等安装结果、失败抛 Win32Exception、Dispose 幂等且卸钩在钩子线程上完成；WinVHook/MouseDragHook 迁移（335d9b4/6fc35e4，回调逻辑零改动，状态只在钩子线程读写，事件仍 Post 回 UI）；App 捕装载失败并托盘回告（9954380）；自查修复发布竞态（6673aac，钩子句柄经回调首参传入）。Core 676/686 全绿、App 构建 0 错误。取词 600ms Sleep 仍冻结本应用 UI（票内明确不改，属票 14 范畴）。

**What to build:**
- `Shiyu.Windows` 里一个专用钩子线程宿主：后台线程装钩并运行自己的消息循环；释放时在该线程卸钩并退出。
- `WinVHook`、`MouseDragHook` 改在专用线程装钩，回调逻辑不变，事件仍 Post 回 UI 线程。
- `SetWindowsHookExW` 失败可见：带回 Win32 错误码；App 回滚为未接管，并用托盘通知说明原因。

**为什么：** 钩子装在 UI 线程，而取词时 UI 线程 `Thread.Sleep` 最长 600 ms。期间全系统键鼠卡顿，钩子还可能被系统静默摘除；开着 Win+V 接管时，迟到的 Ctrl+C 会在剪贴板还原之后覆盖用户剪贴板。
