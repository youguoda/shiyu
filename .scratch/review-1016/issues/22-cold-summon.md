# 22 — 冷呼出复测

**来源：** 评审 F-21
**Status:** ready-for-human

**What to build:** 用 `tools/probes/measure-cold-summon.ps1` 复测热路径与冷路径；热路径若 > 300 ms，轻量模式改为隐藏后延迟 5 分钟再释放。

**验收：** 复测数字写进票；超标则改完再测。

## Comments

- 2026-10-16 复测（本机，Debug 构建；Release 只会更快）：
  - **热路径**（ADR-0006 的真正指标：进程常驻，按快速粘贴到窄条可见、列表排好）。新加 DEBUG 命令 summon-timing 与 `tools/probes/measure-hot-summon.ps1`：在常驻进程里连呼 20 次（先空跑一次），每次收起后停 400 ms 让轻量化做完。

    | 遍 | 轻量模式开 P50 / P95 / max | 轻量模式关 P50 / P95 / max |
    |---|---|---|
    | 1 | 165 / 248 / 253 ms | 175 / 220 / 224 ms |
    | 2 | 179 / 215 / 261 ms | 169 / 219 / 225 ms |

  - **冷路径**（`measure-cold-summon.ps1`，全新进程第一次呼出，各 50 次，两遍取后一遍）：窄条 P50 683 / P95 748 ms，粘贴模式 P95 719 ms。10-03 是 887 / 924 ms。
  - **判定**：热路径 P95 215–248 ms，在 300 ms 门槛内；轻量模式开与关几乎没差（每次呼出本来就重读列表）。按 F-21 的规则**不改**轻量模式，不加"隐藏后延迟 5 分钟再释放"。
  - 冷路径约 0.75 s 是进程启动 + 第一扇窗的造价，只在开机后第一次呼出时付一次。
- **待你过目**：数字是否认可；要在 Release 上复测，需要把 summon-timing 做成非 DEBUG 的开关（目前探针命令只在 Debug 构建里）。
