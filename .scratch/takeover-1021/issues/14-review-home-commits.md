## 发现与处理

1. **探针钩子编进了 Release**（已修，726f4bf）：预览窗工作台探针约 200 行直接写在 `PreviewWindow.xaml.cs` 正文里，连带一个
   `SetCursorPos` 的 P/Invoke；窄条的 `ProbeDragEndedAt`、以及更早（10-19）预览钉 / 反向框钉的几个钩子同样如此。
   Release 程序集里共 36 个 Probe* 名字。原样搬进各窗口 DEBUG 下的 `*Probes.cs`；CI 新增 `no-release-probes` 检查
   （对修复前的代码报 36 个、修复后 clean）——SHIYU_ 扫描只看字符串，抓不到这类。
2. **拖动会「粘」在光标上**（已修，ffec65e）：`LiveDrag` 与窄条、预览窗各自手写的拖动都只等「左键抬起」收尾。拖到一半
   Alt+Tab / Win 键 / 窗被收起，抬起送不到，之后鼠标只是经过窗口，窗口也跟着走；`LiveDrag` 每次按下还多挂一对处理器。
   改为丢捕获即收尾、一扇窗同时一次拖动；窄条与预览窗并回 `LiveDrag`。新探针检查 `flow:bar-dock-capture-lost`：
   旧代码稳定红（丢捕获后窗被带走 335;270 → 515;450），新代码稳定绿。
3. **bar-dock 的拖动探针本身测不准**（已修，同 ffec65e）：合成的按下骗不过系统——真键没按着，捕获随即被收回、抬起被补发
   （跟踪实录），旧的 livedrag 检查在这台机器上时过时不过。改用真实左键（SendInput；按下前确认光标下就是探针自己的窄条、
   左右键未对调，否则 SKIP），读数前等输入落地。
4. **启动时改系统设置「拖动时显示窗口内容」**（52c5e06，**未改，等用户定**）：`DragFullWindows.EnsureOn` 用
   `SystemParametersInfo` 改的是整个会话的设置——机器上所有程序的窗口拖动都跟着变。不写注册表，但拾语开机自启，实际等于
   每次登录都替用户改一次；托盘每次启动都提示一句。这台机器装着向日葵（OrayIddDriver），远程控制软件常为省带宽主动关它，
   拾语一开又被改回。与 CONTEXT「克制打扰」、README「边界就是信任」相冲。机制本身写得对（先读后写、探针旁路、托盘告知）。
   候选：
   - a. 撤掉：系统设置归系统；历史 / 设置两扇系统标题栏的窗口在这种机器上拖动只画外框，和别的程序一样。
   - b. 改成问一句：检测到关着时托盘提示，点了才开（仍是会话级）；不点不改。
   - c. 让历史 / 设置窗也走自绘拖动（LiveDrag），不碰系统设置——它们是系统标题栏，改动最大。
   - d. 维持现状。
5. **缩放卡顿两项探针在这台机器上抖**（未改，记录）：`defect:preview-zoom-jank-large/small` 输入等待 P95 在 33–110 ms 间跳，
   对改动前的 d9790a6 同样时过时不过（45–96 ms）——不是本轮引入。与票 29 记的「小图缩放边缘抖动、待查」同一件事。
6. 小项（未改）：预览窗的双击判定用固定 500 ms，没读系统双击时间；`App.DebugProbes.cs:533` 有一条 Debug 构建的 CS8602。
