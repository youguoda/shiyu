# ADR-0014：大模型的输出按 Markdown 显示（Markdig）

- 状态：已接受
- 日期：2026-10-10
- 依据：用户需求 2026-10-10——"反向输入框和翻译框使用 LLM 输出的文字是 Markdown 格式，展示内容的
  时候要适配 Markdown；翻译记录里可以点击显示全部的内容"

## 背景

自备密钥走的是大模型。模型的输出天然是 Markdown：标题、列表、加粗、代码块、表格，提示词优化
模板整理出来的更是一整篇结构化文字。翻译框与反向输入框原样显示这些字，`**`、`#`、```` ``` ````
全露在外面，读的人要自己在脑子里排版。翻译记录存的也是这份原文，收起时的三行预览同样满是符号，
而且只看得到三行。

## 决策

1. **显示时按 Markdown 排，存与贴仍是原文。** 翻译框的整段视图、反向输入框的输出、翻译记录展开
   的那一行按 Markdown 排；翻译记录收起时的预览去掉标记显示纯文字。复制按钮、存入历史、自动
   复制译文、Enter 贴回，用的都还是模型给的原文——贴去的地方可能本身认 Markdown，存下来的也
   应该是模型真正说了什么。逐句对照视图不变（句子是从整段里切出来的，块结构切不进去）。
2. **解析交给 Markdig，界面只认自己的块树。** Markdig（BSD-2-Clause，约 500 KB，无其它依赖）
   放在 Core 里，读出来马上换成拾语自己的几种块与行内（`MdBlock` / `MdInline`），渲染器不碰
   Markdig。规则在 `MarkdownText` 一处定、一处测：
   - 认：标题、段落、加粗/斜体/删除线、行内代码、围栏代码块、引用、有序/无序/任务列表、分隔线、
     管道表格、链接与裸网址；
   - 单个换行照原样换：模型（和译文）的分行是内容，不能并成空格；
   - 不认缩进代码块：译文里缩进的诗行、引文不该变成等宽代码；
   - 不认 HTML：`<br>` 之类原样显示成字；
   - 图片只显示替代文字，不去网上取图；
   - 链接只有 http、https、mailto 能点开，别的（`file:`、`javascript:`……）只显示不打开；
   - 流式途中没收尾的 `**`、```` ``` ```` 照样读得出，收尾时自然变好。
3. **渲染是一个只读、可选取的 RichTextBox（`MarkdownBox`）。** 排成 FlowDocument：字号与行高
   跟宿主走（内容字号），标题按 1.33 / 1.2 / 1.1 倍、代码按 0.9 倍绑在宿主的字号上，从不写死
   数字；能拖选、Ctrl+C、右键复制。流式中最后一段的末尾挂静态光标块，结算即撤；同一段字不
   重排，用户正在拖的选区不会被抹掉。反向输入框原来"流式 TextBlock、结算换只读 TextBox"的
   两件套合成这一个框，结算时也不再跳一下。
4. **不分后端。** 免费引擎的输出是纯文字，按 Markdown 读出来还是它自己；只有极少数写法会变样
   （比如机器译文里成对的 `*星号*` 会变斜体），接受。

## 后果

- 多一个第三方依赖，发布包多一个 Markdig.dll。
- 翻译框的译文从此能选取复制；代价是它不再是拖动面板的把手（从原文、语言行与空白处照样拖）。
- 流式中每来一段字都整篇重读、重排；常见长度下察觉不到，极长的输出会多花些 CPU。
- 贴回的是原文：贴进不认 Markdown 的地方（例如微信），符号会留在那里——这与以前一样，没有
  在这次改变；要不要"贴纯文字"另议。
