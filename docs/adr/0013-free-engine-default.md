# ADR-0013：首次引导默认"免费引擎"（必应网页接口为主，腾讯交互翻译兜底）

- 状态：已接受
- 日期：2026-10-04
- 修订：ADR-0009 决策 1、ADR-0012 #12（首次引导默认"自备密钥"）
- 依据：Xtranslate 调研（`docs/research/2026-09-27-xtranslate-analysis.md` §4）；2026-10-04 实测（票 41「事实基线」）

## 背景

ADR-0009 把首次引导的默认路径从公共中转收回为自备密钥。它给出的三条理由都针对公共中转：
端点从未部署；`*.workers.dev` 在大陆被整域 DNS 污染；要有人付模型调用费并负责运营。
代价写在它的「后果」里：新用户必须先申请一个 API 密钥，这是一道真实的门槛。

票 41 提出第三条路：直接调用必应翻译与腾讯交互翻译（TranSmart）的网页接口。2026-10-04
直连实测（不经代理）：

- cn.bing.com 取会话 0.40s，短句翻译 0.8s；
- transmart.qq.com 短句翻译 0.21s；
- 两家都能译成拾语设置里的 8 种语言。

ADR-0009 的三条理由对它都不成立：大陆可达，没有我们的服务端，也没有调用费。

但它有自己的风险：

1. **非正式接口随时会坏。** 先例：edge.microsoft.com/translate/auth 自 2026-07-30 起全部返回 404。
2. **服务条款灰色。** 必应这条路要先抓页面里的防滥用令牌（`params_AbusePreventionHelper`），
   再带伪造的浏览器 UA 与 Referer 去调用。性质与票 38 拒掉的 Google 非官方端点同类。
3. **被翻译的文本会发给微软**，兜底时发给腾讯。

## 决策

1. 首次引导的翻译这一屏**预选"免费引擎"**；自备密钥是"更好的质量 + AI 动作"的升级路径。
2. 票 38 曾以"灰色、封禁与合规风险"为由拒掉 Google 端点；这里**接受**必应/腾讯网页接口的
   同类风险。理由：
   - 它们在大陆可达，而 Google 直连超时；
   - "打开就能翻译"的价值；
   - 下面这组缓解措施。

   Google 维持不做。
3. 缓解措施：
   - 必应失败时自动改走腾讯，并冷却 5 分钟。单个接口坏了，不等于翻译坏了。
   - 网络探针（直连与走代理各跑一遍）写进发布检查清单，非正式接口坏了要在发版前发现。
   - 设置与引导里写明：文本发往哪里；"这是网页接口而非正式 API，可能随时变更或限流"。
   - 批量翻译、Agent 动作、LLM 词典仍只走自备密钥，批量请求不打网页接口。
4. 存量用户一律不动。`AppSettings.TranslationBackend` 的类型默认值仍是 `OwnKey`：
   - 只有走完引导翻译这一屏（看过披露）的新用户才写入 `Free`；
   - 选"跳过，用默认设置"的用户仍是自备密钥，首次翻译时由未配置引导卡提供一键切换。

   这守住了 AppSettings 的原则：文本发往哪里，不做静默升级。

## 后果

- 新用户不必申请密钥就能翻译，ADR-0009「后果」里的那道门槛对大多数人消失了。
- 拾语多了一项外部依赖：两家网页接口的形状。接口变了只能发版修复，修复路径是自动更新
  通道（票 28）。
- 免费引擎没有 prompt：提示词模板（票 42）在免费引擎下不生效，面板上的模板按钮隐藏。
- 公共中转"零配置"的价值大部分被覆盖。

## 回头选项

- 两家接口长期不稳定，或收到权利方异议时，撤回本 ADR：引导默认退回自备密钥
  （ADR-0009 决策 1），免费引擎降为可选项或下线。
- ADR-0009 的"回头选项"（把公共通道设为默认）改为：免费引擎失效且无法修复时再议。
