# ADR-0001：翻译的触发模型

- 状态：已接受（决策 1 于 2026-10-13 修订：徽标默认关闭，由用户打开）
- 日期：2026-09-21

## 背景

应用同时承担两个挂在剪贴板监听上的职责：翻译复制内容（功能 #1）与记录复制历史
（功能 #2）。两者对触发的要求相反——历史要贪婪，翻译要克制。

用户一天中绝大多数复制是代码、文件路径、URL、命令行。若每次复制都自动翻译并展示
译文，噪音将高到使应用无法长期驻留；若翻译走云端，还等于把每一次复制都上传。

## 决策

1. **翻译不自动展示。** 复制后仅在光标旁出现**徽标**，点击才展开**面板**。

   → 2026-10-13 修订（用户需求）：徽标改挂在「翻译徽标」总开关下，默认关闭；拖选徽标是它的
   子项。默认的翻译入口因此是划词翻译与翻译剪贴板两个热键。用户打开开关后本条照旧：只出徽标，
   点击才展开面板。
2. **徽标有出现条件。** 先过自然语言过滤器（挡代码/路径/URL/纯数字），再过语言检测，
   仅当内容像自然语言且非中文时出现。
3. **方向单一。** 徽标只做外→中。中→外走逃生热键与面板内方向切换。
4. **逃生热键为必选。** 过滤器必然误判，没有兜底则"该弹没弹"与"程序崩了"无法区分。
5. **徽标与面板不接受焦点。** 必须是 `WS_EX_NOACTIVATE` + `WS_EX_TOPMOST` 一类窗口。
6. **徽标定位在光标旁。** 接受由此带来的多显示器 / per-monitor DPI 坐标复杂度。

## 后果

**正面**

- 未经点击的文本永不离开本机——隐私问题在触发模型层面就解决了，不依赖后续的后端选择。
- 无谓的翻译调用降为零，对延迟与（若走云端的）成本都有利。

**负面 / 成本**

- 引入两个依赖：自然语言启发式过滤器、轻量语言检测（n-gram 类，不用模型）。
- 引入一类新 bug：**该弹没弹**。比"弹多了"更难排查，逃生热键是唯一缓解。
- 徽标定位必须按 per-monitor DPI aware 实现，多显示器混合缩放是明确的测试重点。
- 第 5 条（不接受焦点）会**淘汰部分 UI 技术方案**，是技术栈选型的硬输入。

## 被推翻的备选

- **每次复制都自动翻译** — 噪音不可接受，且等于全量上传。
- **每次复制都弹徽标（不过滤）** — 曾短暂选中，因一天两百次闪烁把全部压力压在
  徽标的"可无视性"上，容错率过低而推翻。代价是换回了上面两个依赖。
