# ADR-0004：剪贴板历史的范围与存储策略

- 状态：已接受
- 日期：2026-09-21

## 背景

原始需求"对我复制信息整理"极其模糊。经澄清，用户要的是**Windows 原生剪贴板
历史的增强版**，而非 LLM 驱动的自动归纳。

这与"内存小、启动快"的硬约束存在真实碰撞：无限历史 + 图片存储会让磁盘无界增长。

## 决策

### 功能范围

全格式存储（文本 / 图片 / 链接 / 文件路径）、按项目与用途分类标记、置顶、
关键词搜索、多维筛选（关键词 / 日期 / 内容类型）、图片缩略图、
条目可拖拽至资源管理器另存为文件。

### 存储架构

1. **嵌入式数据库 + 磁盘 blob**（SQLite + 文件），不是 JSON、不是内存结构。
   无限历史、全文搜索、多维筛选、启动快——四者同时成立只有这一种做法。
2. **历史绝不加载进内存**。一律按需查询。这是"内存小"在本模块的具体含义。

### 保留策略

- **文本 / 链接 / 文件路径：真·无限**，永不删除。体量小，且是日后唯一会被搜索的内容。
- **图片缩略图：永久保留。** 历史列表因此永远完整，不出现空洞。
- **图片原图：有保留期**（可配置，默认约 90 天）。超期仅影响"拖出去另存"，不影响识别。

（2026-10-16 补注：功能评审 F-13b 之后加了「历史保留」：7 / 30 / 90 天 / 永不，**默认永不**——
不动设置的人看到的仍是上面的"真·无限"。选了周期，到期条目整条删除（文字、文件、图片都算，图片
连缩略图带原图），受删除保护的收藏与置顶不删。只清文字、留着图片缩略图不合隐私敏感用户的预期：
他们要的是"多久以前的都别留"，与翻译记录的周期同一套语义。）

### 敏感内容排除（强制）

应用**必须**识别 Windows 的剪贴板排除标记（`ExcludeClipboardContentFromMonitorProcessing`、
`CanIncludeInClipboardHistory` 一类格式），密码管理器等以此声明"勿记录"。

不实现此项的后果是：把用户所有密码明文永久存盘。故此项非可选。

> **待验证**：上述格式的确切名称与行为未经一手来源核实（用户选择跳过技术调研）。
> 实现前需核对 Microsoft 官方剪贴板文档。

## 后果

- 磁盘占用有界，同时"找不回东西"的恐惧被完整消除——用户真正在意的是可检索性，
  而可检索的内容全是文本。
- **拖拽至资源管理器另存需实现 OLE 拖放源（`IDataObject`）**，是一块独立的、
  分量不轻的工作，单独开票，不阻塞主干。
- 分类标记为人工维护。已知风险：手工标签体系普遍难以长期坚持。
  是否引入 agent 辅助打标签，见 ADR-0005。

## 被推翻的备选

- **真·无限全存原图** — 最贴合"不怕丢"的字面要求，但一年数十 GB，
  与"小而精美"不符。
- **分层限额全可配** — 最灵活，但设置项膨胀，与克制的产品气质相悖。
- **不存图片** — 磁盘压力归零，但用户明确要了缩略图与拖拽另存。
- **LLM 自动归纳全部复制内容** — 绝大多数复制内容是器物，归纳产出亦然；
  且需逐条外送，成本与隐私均不划算。
