## 0. 结论

**一句话：拾语已经从"能用的原型"走到了"可以推荐给同类用户的 0.x 产品"。功能面完整、原则一致、
工程纪律在个人项目里罕见。下一阶段的瓶颈不再是功能数量，而是三处"最后一米"。**

三个判断：

1. **上一轮的债还清了。** 10 月 1 日评审的 4 个 P0、12 个 P1 对应的 v3 票 30 张里 28 张 done
   （剩 05 公共通道服务端加固、30 提权窗口贴回两张 ready-for-agent）。交付链（CI、签名更新、安装包、
   真装真卸冒烟）、信任链（DPAPI 按服务商分格、密钥只发给所属服务商、更新验签无 fail-open）、
   可靠性（全局异常、日志、SQLite 加锁、钩子专用线程）都已落地并有探针守着。
2. **功能广度够了，别再横向加。** 记（全格式 + 排除）、取（窄条 + 管理窗）、懂（面板 + 词典 + 逐句 +
   朗读）、说（反向输入框）、思（四个动作）、守（本机 + 披露）六层都有东西。设置项已从评审时的
   36 项涨到 56 项，CONTEXT 里"设置项越少越可信"的原则正在被一个个开关稀释。
3. **三处"最后一米"决定它能不能被人留下来**：
   - **信任门槛**：安装包没有代码签名，每个新用户第一眼是 SmartScreen 的红色警告（F-01）。
   - **贴回去那一步**：Markdown 符号贴进微信（F-02，已知问题挂了 4 个版本）、提权窗口静默吞掉
     （F-03，挂了 7 个版本）、默认热键盖掉浏览器与聊天软件的"粘贴为纯文本"（F-04）。
   - **图片这条线没打通**：截图既搜不到也译不了（F-07）。对一个"拾 + 语"的产品，这是最大的空白。

**建议**：用两个版本（约 3 周）收口第一、二处，再开"翻译第二曲线"（OCR、本地词典、生词本、自然音色）。
期间横向功能冻结；凡在 CHANGELOG「已知问题」里连挂两个版本的条目，自动升为 P1 票。

## 4. 资产：必须保护、不能回退的

1. **面板从不抢焦点**（`WS_EX_NOACTIVATE` 三重保障 + `ZBand` 编译期约束）——划词翻译不破坏选区，是面板能"陪着读"的前提。
2. **就地键帽与单一键位表**（`KeyMap` 七个渲染面同表）——按住 Ctrl 的那一瞬间教会整套键盘模型，提示永远不会错键。本次截图确认零位移。
3. **反向输入框的回贴链路**（`ForegroundReclaim` → 条件还原 → 序列号判定）——这是最难做对的 50 行，0.16.1 之后已能在剪贴板被抢的情况下自愈。
4. **排除规则是唯一闸口**（`CaptureGate` / `ExclusionPolicy`）——取词、徽标、动作、翻译记录都过同一判定点。
5. **"不点不发"**——没有任何后台的、自动的模型处理；免费引擎不是通用模型，批量与动作不打网页接口。
6. **流式节拍与块级重排**（`RenderCadence` / `StreamRefresh`）——探针实测 5040 字译文输入延迟 p95 4 ms。
7. **诚实的披露文案**——翻译方式、免费引擎、数据位置、卸载删数据，每一处都说清"文本发往哪里"。
8. **发布纪律**——release notes 里的每个功能能在该 tag 源码里指出来源（票 38 守则）；免费引擎探针进发布清单。

## 5. 问题与建议

> 工作量：S ≤ 半天，M = 1–3 天，L ≈ 一周。每项都给**可观察的验收**。

### 5.1 P0 — 挡在"推荐给别人"前面的

#### F-01 · 安装包没有代码签名 · M（主要是流程与钱）

- **现象**：ADR-0015 #8 有意暂缓；README 教用户点"更多信息 → 仍要运行"。
- **为什么是 P0**：这是新用户与拾语的第一次接触，也是一个常驻、自启、读剪贴板的程序最不该出现的第一印象。
  其他发布阻断项都已清掉，它成了唯一一道门槛。
- **做法**：二选一——① 购买 OV 代码签名证书（数百美元 / 年量级，硬件令牌）；② Azure Trusted Signing
  （按月订阅、个位数美元量级，证书短期轮换，GitHub Actions 有现成动作；个人开发者的身份验证有地区限制，需先核实）。
  签 `shiyu-win-x64-setup.exe` 与 `Shiyu.App.exe` 两处。ADR-0010 的 ECDSA 验签保留（它管的是更新链）。
- **验收**：全新 Windows 11 虚拟机下载安装包，首次运行无 SmartScreen 警告；`signtool verify /pa` 通过。

#### F-02 · 反向输入框贴回的是 Markdown 原文 · S

- **现象**：CHANGELOG 自 0.13.0 起连续 4 版列为已知问题。反向输入框的目标就是聊天框（README 的示例是微信），
  而聊天框不认 `**`、`#`。
- **做法**：`MarkdownText` 已把输出解析成块树（ADR-0014 决策 2），加一个"渲染为纯文本"的访问器：
  标题去井号、强调去星号、列表换成 "- " / "1. "、表格按行 Tab 分隔、代码块保留原文。反向输入框的 Enter 贴回
  **默认用纯文本**；面板的「复制」加一项「复制纯文本」（或按住 Shift）。原文仍进翻译记录。
- **验收**：模板「提示词优化」的结果贴进记事本，不含任何 `*`、`#`、```` ``` ````；贴进 VS Code 的 Markdown
  文件时可通过「复制」拿到原文。

#### F-03 · 提权窗口贴不进，译文既没贴上也不在剪贴板 · S–M

- **现象**：v3 票 30 ready-for-agent，CHANGELOG 自 0.10.0 起 7 版已知。任务管理器、管理员终端、以管理员运行的
  编辑器都会撞上。
- **做法**：贴回前比较前台进程与自身的完整性级别（`OpenProcess` + `GetTokenInformation(TokenIntegrityLevel)`；
  打不开进程本身就是"比我高"）。高于自身时：不发 Ctrl+V、不还原剪贴板，把译文留在剪贴板上，InfoBar 提示
  "目标窗口以管理员运行，译文已复制，请手动粘贴"。划词取词同理（提示而不是沉默）。
- **验收**：在管理员 PowerShell 里 Alt+Q 打字回车，看到提示，Ctrl+V 能贴出译文；普通窗口行为不变。

#### F-04 · 默认热键盖掉近乎通用的快捷键 · S（改默认）+ 决策

- **现象**：`Ctrl+Shift+V` 是浏览器、聊天软件、Windows Terminal 的"粘贴为纯文本 / 粘贴"，`Ctrl+Shift+Z` 是
  许多编辑器的"重做"，`Alt+Q` 是 Microsoft 365 的搜索框。目标用户（开发者、办公）每天都会撞上；
  CHANGELOG 把它列为已知问题，但"冲突了就改键"把成本推给了用户。
- **做法**：只改**新安装**的默认值，存量设置不动。候选：快速粘贴 `Ctrl+Alt+V` 或 `Ctrl+``；划词 `Ctrl+Alt+Z`；
  反向输入 `Ctrl+Alt+Q`。引导第 3 屏（呼出）已有键帽录制器，加一行"这些键会盖掉其他应用里的同名快捷键"，
  并对已知冲突（Ctrl+Shift+V / Z、Alt+Q）就地提示。
- **验收**：全新安装后在 Chrome 地址栏 Ctrl+Shift+V 仍是纯文本粘贴；引导里改键即生效。
- **需要你拍板**：见 §8 D2。

#### F-05 · 设置与引导里有一项永远选不了的"公共通道（即将推出）" · S

- **现象**：`SettingsSchema.cs:272` 的三段选择里第一段灰显不可选，并附一大段"上线条件未满足"的说明；
  首次引导的翻译屏也有一张点不动的"公共通道 · 即将推出"卡（`OnboardingWindow.cs:735`）；
  README 也写"面向所有人的公共翻译通道尚未开放"。
- **为什么**：ADR-0013 之后免费引擎覆盖了它"零配置"的大部分价值；它需要有人付费运营；服务端加固票（v3-05）
  仍未完成。一个占着首位、选不了的选项只会让用户多想一次"我的文本到底发给谁"。
- **做法**：界面上隐藏它（`RelayBackend` 与 `server/` 代码保留、冻结），ADR-0009 的"回头选项"改写为
  "免费引擎失效且无法修复时再议"（ADR-0013 已有此句）。
- **验收**：设置与引导里翻译方式只剩"免费引擎 / 自备密钥"两项；探针 `flow:*backend*` 相应更新。

### 5.2 P1 — 同类用户会问"怎么没有"的

#### F-06 · 没有"暂停记录" · S

- **现象**：代码里没有任何暂停 / 隐私模式（`grep` 零命中）。共享屏幕、处理不在排除名单里的敏感内容、演示时，
  用户只能退出拾语。
- **做法**：托盘菜单加「暂停记录 15 分钟 / 1 小时 / 直到恢复」，托盘图标换灰态；可选热键。暂停期间剪贴板监听
  照常收 `WM_CLIPBOARDUPDATE` 但管道不落库、不弹徽标；到时自动恢复并托盘提示。
- **验收**：暂停期间复制 3 条，历史无新增；恢复后复制 1 条，历史新增 1 条。

#### F-07 · 图片是黑盒：搜不到、译不了 · M

- **现象**：图片条目只存缩略图与原图；窄条搜索、管理窗搜索对截图无效；翻译的三个入口都只认文本。
  对"一天复制几十次，其中不少是截图"的用户，这是一整条没打通的线；对翻译而言，**截图翻译**是 Pot 一类工具的核心入口。
- **做法**：用 Windows 自带的 `Windows.Media.Ocr`（离线、免费、随显示语言装中英识别包）：
  ① 入库后在后台线程对图片 OCR，文本写入 `entry_blobs` 旁表并进 FTS，卡片上标一个小字形"含文字"；
  ② 面板加"翻译这张图"：剪贴板是图片时 Ctrl+Shift+X 直接 OCR → 翻译，走现有管线；
  ③ 窄条动作加「复制图中文字」。
  前提是把 `Shiyu.Windows` 的目标框架改成 `net9.0-windows10.0.17763.0`（最低版本仍可设到 Win10），
  这与 F-10 共用一个前置。OCR 是本地确定性计算，不违反"不点不发"。
- **验收**：复制一张含中文的截图，窄条搜其中的词能命中；Ctrl+Shift+X 出译文；OCR 不占 UI 线程（探针断言输入延迟）。

#### F-08 · 英文词典卡的释义是英文 · M

- **现象**：`FreeDictionaryApi.cs:14` 只有英文释义；`FallbackDictionary` 的注释记录了它在部分网络下完全不可达；
  中文解释只有那一行由翻译给出的"答案"。面向中文读者的词典卡，释义本身应该是中文。
- **做法**：内置一份本地词典。ECDICT（MIT，CSV / SQLite，带中文释义、音标、柯林斯星级与考试标签）是现成的；
  取常用词子集（几万到十几万词）控制体积，查词零延迟、离线、不出机器；dictionaryapi.dev 降为例句补充，
  LLM 仍兜底生僻词与中文词。
- **验收**：断网状态下划词 "example"，词典卡立即出中文释义与音标；体积增量写进 CHANGELOG。

#### F-09 · 没有生词本 · S–M

- **现象**：README 结语说"它不只替你翻，也愿意陪你学"，但词典卡上没有"记下这个词"，翻译记录也不区分查词与译句。
- **做法**：词典卡加星标；翻译记录页加「生词」筛选；导出 CSV（Anki 可直接导入）。数据已在 `translation_log`，
  加一列即可。
- **验收**：收藏 3 个词后在管理窗「翻译记录 → 生词」看到 3 条，导出的 CSV 含词头、音标、释义、原句。

#### F-10 · 朗读用的是 SAPI 老音色 · M

- **现象**：`Speech.cs` 走 `System.Speech`（SAPI 5），只能看到上一代桌面音色（慧慧、Zira 等）。
  Windows 11 的 OneCore 与可下载的自然音色要走 WinRT 的 `Windows.Media.SpeechSynthesis`。
- **做法**：与 F-07 同一个前置（WinRT 目标框架）；按译文语言挑音色，优先自然音色，找不到回落 SAPI；
  朗读中按钮变为"停止"（现在是同一按钮再点即停，但没有视觉状态——需实机确认）。
- **验收**：中文译文朗读使用 OneCore / 自然音色；装了自然音色的机器上能选到。

#### F-11 · 取词靠模拟 Ctrl+C，是全应用最脆的一带 · S（spike）+ 决策

- **现象**：ADR-0003 有意只走 Ctrl+C。0.16.1 的 7 条修复全部在"借剪贴板 → 读 → 还"这条路上：
  被占着就崩、还原误报、截图工具被提前收工、格式丢失、用户自己的复制被撤掉。0.16.1 之后已经大为稳健，
  但这条路的本性是"每次取词都动一次剪贴板"，拖选徽标尤其如此。
- **做法**：做一个 S 级 spike——UIA `TextPattern.GetSelection()` 在 Chromium / Electron / Office / WPF /
  WinUI / 记事本 / 微信 / Acrobat 上的实际覆盖率，各测 20 次。覆盖率够就改成"UIA 先试、Ctrl+C 兜底"：
  常见应用不再借剪贴板，拖选徽标可以不发 Ctrl+C 只问 UIA 有没有选区。覆盖率不够就把 spike 结论写进
  ADR-0003，此议永久关闭。
- **验收**：spike 报告一张表；若采纳，`probe-capture-restore` 的六个场景在 UIA 路径下剪贴板序列号零变化。

#### F-13 · Windows 10 不承诺，也没验过 · S

- **现象**：README 写明"未做验收，不承诺可用"。国内 Windows 10 存量仍可观；代码里 Mica、圆角、DWM 属性都是
  Win11 特性，理论上会降级，但没人看过。
- **做法**：在 Windows 10 22H2 虚拟机跑一遍 `run-all` 与手工清单 A–D；按结果二选一——写进系统要求并在安装包里
  检测版本给出明确提示，或把降级路径修到可用。
- **验收**：README 系统要求一句话能说清；安装包在 Win10 上要么可用、要么清楚地拒绝。

#### F-13b · 剪贴板文本永不自动清理，与翻译记录不对称 · S

- **现象**：`RetentionService` 只清图片原图，文本"真·无限"（ADR-0004）；翻译记录却有 7 / 30 / 90 / 永不。
  隐私敏感的用户会期待同一套语义。
- **做法**：「记录与隐私」加"文本保留"四选一，默认永不；收藏与置顶受删除保护不参与。
- **验收**：选 30 天后，31 天前的普通文本条目在下一次清理后消失，收藏的仍在。

## 6. 竞品位置

> 来源：本仓库三份调研（TieZ、Glossy、Xtranslate）与公开资料；只列能站得住的差异，不做逐项打勾。

| | 剪贴板历史 | 翻译 | 拾语的位置 |
|---|---|---|---|
| **Windows 自带（Win+V）** | 25 条、无搜索、可云同步 | 无 | 拾语能接管 Win+V；对"够用就行"的用户，拾语的卖点是搜索、无上限、不上传 |
| **Ditto** | 成熟、分组、跨机同步、顺序粘贴 | 无 | 拾语缺顺序粘贴（F-12）；赢在界面、隐私预设与翻译 |
| **EcoPaste / TieZ** | 跨平台、同步（TieZ 明文）、主题 | 无 | 拾语在排除标记、密码管理器预设、测试与更新链上领先；刻意不做同步是正确的差异化，前提是备份要省心（F-20） |
| **PowerToys Advanced Paste** | 粘贴为纯文本 / Markdown / JSON，接 OpenAI 做转换 | 无 | 微软背书的"AI 加工剪贴板"；拾语的反向输入框与模板是更贴近写作场景的版本，但纯文本贴回反而是 Advanced Paste 做得更好的事（F-02） |
| **Pot** | 无 | 划词、输入翻译、**截图 OCR 翻译**、多引擎对比、插件、生词导出 | 翻译广度上 Pot 领先；拾语的流式、逐句、不抢焦点、反向输入、与历史联动是深度优势。F-07、F-09 补的正是最显眼的两块 |
| **有道 / DeepL 桌面** | 无 | 生态完整、质量稳定 | 不同赛道；拾语的立足点是"不换工具、不离开光标" |

**判断**：拾语不该去追 Pot 的引擎数量或 TieZ 的功能面板。它的赛道是"一个托盘程序，把复制、读懂、写出三件事
放在光标旁边"。这个定位成立的条件是三件事各自做到"够深"，而不是六层各自"够广"。
