# 拾语深度测试调研报告——应该考虑哪些方面

- 更新：2026-10-23
- 方法：代码走读（11 个功能模块、窗口层、数据层、更新与分发链）+ 既有测试资产盘点
  （docs/test-plan.md、docs/full-test-report.md、manual-test-v3~v6、testing/、票 29）
  + 2026-10-20~23 四轮实测记录。
- 定位：docs/test-plan.md 回答「已有的测试怎么跑」；**本报告回答「还应该测什么、
  为什么、怎么测、先测哪个」**。每节给：现状 → 差距 → 建议方法 → 优先级
  （P0 = 发布前必补，P1 = 一个版本内，P2 = 排期）。

## 0. 被测对象画像（风险从结构来）

拾语 = 常驻后台的剪贴板管理 + 翻译工具。结构上它同时是：

| 形态 | 组成 | 一旦出错的代价 |
|---|---|---|
| 常驻进程 | 托盘 + 剪贴板监听 + 全局热键 + 钩子 | 静默丢记录、占资源、被杀软误杀 |
| 数据管家 | SQLite 历史 + 图片档 + 翻译记录 + 备份 + 保留期清理 | **用户数据丢失/损坏 = 不可逆** |
| 五类浮窗 | 窄条、预览、翻译面板、反向框、徽标（全部自绘/透明） | 视觉与焦点问题直接可感 |
| 两扇常规窗 | 历史管理窗、设置窗（系统标题栏 + Mica） | 常规桌面应用问题 |
| 网络客户端 | 自备密钥 LLM、免费引擎（非官方接口）、中转 | 隐私、配额、接口失效 |
| 分发链 | Inno 安装器 + CI 构建 + ECDSA 验签更新器 | 升级变砖、验签失效 |

风险最高的三块：**数据完整性**（丢了找不回）、**常驻资源**（7×24 跑）、
**全局输入钩子**（影响整台机器的手感）。测试资源应向它们倾斜。

## 2. 使用逻辑维度（状态机与交互组合）

现状：模式类状态机有单元测试（ReverseInputSession 87 条、PreviewPolicy 28 条、
BarKeyboard 5 条），探针驱动主路径。缺口在**状态组合与快速交替**：

- **窄条的键态×窗态矩阵**：搜索态/选中态 × 未钉/钉住/贴边收起/贴边展开 ×
  召出/常驻——每个组合下按字母、Ctrl+字母、方向键、Enter、Esc 的行为表
  （bar-keys 探针已覆盖 5 格，全矩阵约 40 格，建议表驱动补全）。
- **预览的三重身份**：未钉悬停 / 钉住工作台 / 拖动中——与窄条的收起、召出、
  贴边收起互相作用时的归属（workbench 探针覆盖 8/16 组合）。
- **快速交替**：1 秒内连续召出-收起、连续开关贴边、钉住-取消钉连打十次、
  预览连开十张卡——**竞态类缺陷的高发区**（票 29 的叠印就是交替态残留）。
  建议做成「交替探针」：随机事件流 + 终态断言（模型检查的简化版）。
- **中断恢复**：每个动画/延迟收起的中间态被新事件打断（贴边滑动中收起窗、
  淡出中重新召出——淡出已处理，滑动是新增，需要同等对待）。

方法：把上面每个矩阵写成表驱动探针（种子 + 事件序列 + 终态断言），挂 run-all。

## 3. 性能维度

现状：呼出/流式/预览/解码/贴边动画有预算与探针（test-plan.md §3 表）。
缺口：

- **大数据量**：现在种子只有 20 条、真实库 731 条。要建 **5 万/10 万条**的
  压力库：窄条呼出与滚动、管理窗搜索、筛选、导出、保留期清理的耗时曲线。
- **低配机画像**：软件渲染实验（票 07）已证明渲染开销可控；还应测「无独显 +
  150% DPI + 机械盘」的组合——那是部分真实用户的机器。
- **启动时间**：冷启动目前只靠 measure-cold-summon；应加「登录自启场景」
  （与系统争 IO 时启动）的读数。
- **贴边滑出节奏**：bar-slide 探针已量化（14.8 帧/162ms）；预算值待你定
  （建议：帧隙中位 ≤20ms、最大 ≤40ms、全程 ≤250ms）。
- **翻译首字延迟**：自备密钥与免费引擎各自的首字延迟目前无预算——用户对
  「按下热键到看见第一个字」最敏感，建议 ≤1.5s（免费引擎）。

方法：预算写进探针（现有 perf: 模式），每轮 run-all 出趋势；超预算的查因
模式照票 07（先分清固定开销与泄漏）。

## 4. 资源维度（内存/句柄/磁盘）

现状：churn 探针测了预览 30 轮（工作集 0 增长）；票 07 测过软件渲染的固定开销
（私有 134→58MB、句柄 2208→689）。缺口：

- **长时 soak**：**8 小时 / 72 小时**挂机探针——每 30 分钟执行一轮「复制-预览-
  翻译-粘贴」混合负载，记录工作集/私有/GC/句柄/GDI 对象数的曲线。判定规则：
  单调增长超 20% = 泄漏嫌疑；锯齿回到基线 = 健康。这是「常驻软件」的命门。
- **图片档膨胀**：30 天保留期下，高频截图用户（每天 200 张 4K）的磁盘占用
  与清理及时性——清理跑完目录应收缩。
- **数据库增长**：10 万条历史时的查询延迟（管理窗搜索 P95）与库文件体积。
- **备份堆积**：定期备份只留最新 N 个——N 次误触发不应无限增长（已有探针，
  但建议加体积口径）。

方法：soak 探针（复用 run-all 的种子 + 计时采样，输出 CSV 曲线）+ 每次发版
把 1 小时读数记进 release-checklist（清单已有此项，执行率待落实）。

## 5. 可用性 / 快捷性 / 可访问性维度

现状：a11y 检查 4 项（按钮可达名）、教学行与首用提示有探针。缺口：

- **按键经济性审计**：数一遍高频操作的最少击键（复制=？、翻译=？、钉=？），
  与竞品（Ditto、PasteBar）对比；「选中态直接按字母动作」这类设计（票 530c019）
  就是这一维的产出，应制度化：每个新交互先过一遍「能不能少一键」。
- **可发现性**：功能被找到的路径——首用提示只覆盖两处；钉住、贴边、模板
  自定义这些功能，新用户第几天能发现？（可以用「5 秒截图测试」：每个界面
  截图给没见过的人猜功能。）
- **错误文案**：每个会失败的操作（密钥错、网络断、路径没了、备份锁住）的
  文案是否「说人话、给出路」——探针已抽查三处，建议做成清单全量核对。
- **可访问性深化**：现有 a11y 只查「有名字」；还应测：高对比度主题、
  200% DPI、屏幕阅读器（Narrative 顺序）、纯键盘走完设置窗全部页。
- **减少动效**：系统「减少动效」下所有动画一步到位——已贯彻（贴边滑动、
  预览淡出），建议做成一次性全窗口核对清单。

方法：可用性没有断言，用「清单 + 截图 + 人」；每条发现问题转化为缺陷票，
修完加探针守卫（票 29 的模式）。

## 6. 可靠性与故障注入维度

现状：备份锁文件、设置保存重试、剪贴板竞争还原已有覆盖。缺口（全部可用
「注入」手段自动化）：

- **磁盘满**：历史库/图片档所在盘剩余 0 时复制——记录失败要有托盘提示且
  不丢当前剪贴板。
- **杀毒锁文件**：设置/历史库被占用 1–5 秒——已有三次重试；应测超时后的
  降级（不丢数据、提示准确）。
- **进程被杀**：写入中途 kill -9——重启后库完整性（SQLite 应自愈）、
  备份可恢复、无半截图片档。
- **更新中断**：下载 99% 断网、验签失败、暂存目录被清——三路都有单元，
  缺端到端探针（可用假更新源注入）。
- **单实例互斥**：同目录双开拒绝、异目录并跑放行（run-all 有 SKIP 版，可
  补负路径）。
- **以管理员/非管理员混用**：目标窗口是管理员权限时粘贴降级路径（已有票），
  应补探针。

方法：每个故障写一个「注入探针」（现有 DebugOverrides 的旁路机制就是为此
准备的），故障注入后断言「提示准确 + 数据完好 + 可恢复」。

## 7. 安全与隐私维度

现状：更新验签（ECDSA）、密钥 DPAPI、中转匿名 id、卸载删数据均有单元。
缺口：

- **剪贴板内容即不可信输入**：含脚本的 HTML、超长 Markdown、伪造成分的
  路径（`..\..\`）进入历史/预览/Markdown 渲染——应有一组「恶意内容」种子
  走完整链路，断言不崩、不外发、渲染转义。
- **本机边界**：历史库与图片档未加密（设计如此，隐私开关管录入）——但
  「翻译外发」的边界要钉死：只有用户主动翻译才出网、排除名单绝对拦截
  （SelectionBadgeFilter 15 条已有，建议加端到端断言：钩子在、名单命中、
  网络零请求）。
- **中转匿名性**：client id 与内容无关联、无设备指纹外泄（已有一节，建议
  补一次抓包核对）。
- **卸载与数据主权**：卸载「同时删除数据」后目录应为空（已有 6 条单元 +
  安装器冒烟）。

方法：恶意内容种子进 seed.ps2/seed 旁路 + 抓包核对；一次渗透式自查
（更新器与中转两个面）足够，不需要常态运行。

## 8. 兼容性维度

现状：Win10 退化外观、全屏抑制、系统减少动效、DragFullWindows 代开已有覆盖。
缺口：

- **多屏混合 DPI**：150% 主屏 + 100% 副屏，窄条/预览跨屏拖动与锚点
  （AnchorFor 已按此设计，无探针）。
- **IME 场景**：中文输入法激活时，热键与全局钩子的行为（输入法吞键）。
- **第三方共存**：与其他剪贴板管理器同时监听时的顺序与争用
  （capture-restore 已测竞争，可扩展）。
- **系统设置族**：减少动效 ✓、DragFullWindows ✓（代开）、高对比度（未测）、
  任务栏自动隐藏（窄条在其上方时的遮挡）、深浅色切换瞬间（tooltip 探针
  已测，其他窗建议补）。

方法：兼容性项多为「一次性核对清单」+ 个别常驻探针；建一张
「系统设置 × 窗口」矩阵，逐格核对一次，之后只在新窗口类型出现时补。

## 9. 长期运行与升级维度

现状：升级链有单元与发布核验；数据搬迁有提示机制。缺口：

- **跨版本升级链**：0.16 → 0.17.x → 0.18 实机连升（保留历史与设置），
  每步启动一次——设置模式演进（SettingsSchema 34 条单元是保护网）的
  端到端验证。
- **保留期跨版本**：旧版本写入的记录在新保留期规则下的清理行为。
- **数据目录搬迁**：改目录 → 提示重启 → 重启后旧目录残留与引用一致性
  （有单元，缺端到端）。

方法：建一台「升级测试机」镜像（或虚拟机快照链），每次发版前走一遍链；
这是发布核验清单「更新通道实测」的固化形式。

## 10. 方法论（怎么以高级测试工程师的方式驱动这些）

1. **风险驱动**：按 §0 的代价表分配精力——数据完整性 > 常驻资源 > 全局
   输入 > 视觉。每个新功能先问「坏了的代价是什么」。
2. **缺陷即资产**：每次发现缺陷（如票 29 的 13 项）按「探针 + 票 + 根因」
   固化——本仓库已形成此模式，保持。
3. **探索性章程**：每轮人肉测试给一张章程卡（例：「章程：与贴边窄条的
   菜单交互 45 分钟，目标是找到收窄条的任何路径」），结束后写发现。比
   「随便点点」的产出高一个量级。
4. **组合矩阵思维**：§2 的状态矩阵是这类常驻工具缺陷的主产地；新功能
   先画状态表，再挑高风险格自动化。
5. **度量与趋势**：run-all 的 PASS 数、预算表、soak 曲线每版记录——
   「变慢了/变重了」只有靠趋势才能看见。
6. **自动化优先级**：能进 run-all 的进 run-all；真鼠标/真剪贴板的放
   手动清单并写明守卫；一次性的写进本文 §5 清单。
